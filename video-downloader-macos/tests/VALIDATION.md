## 第二轮对抗式审查（2026-09-24）

界面已删除「把不好用的地方改一改，再分享给你」。保留 Mac 预览状态说明。

发现并修复：

- 初次启动超时可能留下刚启动的后台：失败时只处理本次持有的 ChildProcess；进程已退出时不依据旧 PID 执行关闭。
- 就绪检查原先只判断组件字段真假：改为严格 true，并核对 macOS、芯片架构和正在停止的状态，避免把错误服务报告为可用。
- 原先继承 NODE_OPTIONS / NODE_PATH：入口和后台启动都会清掉这两个进程环境变量，避免继承调试端口或额外加载模块；不修改系统设置。
- 停止前任务接口的非成功响应未单独检查：现在请求失败或返回结构错误时拒绝继续停止。
- 查询后台超时原先会被当成未运行：现在仅连接被明确拒绝时按无监听处理；已有端点未响应或状态异常时拒绝开始/停止，避免重复启动或误报已停止。新增实际 HTTP 端点不响应的故障测试。

新增 `tests/service-macos.js` 使用真实的隔离本机 HTTP 测试端点，以及可观察的模拟子进程，覆盖：重复启动不新建进程、旧构建/错误系统/错误芯片/组件缺失拒绝就绪、Windows/其他安装不受停止操作影响、正在下载时拒绝停止、预检查后新任务出现时遵从服务端拒绝、旧构建的正确停止、启动超时清理、提前退出与启动异常、Node 环境变量隔离。它不启动或终止用户的真实下载器进程。

原有源码、组件校验、Mac 系统接口适配、HTTP 安全与下载完整性检查继续执行；最终源码 ZIP 另验无运行文件/个人配置、脚本使用 LF 且保留可执行位。以上仍不能代替 Mac 实机首次安装和 UI 验收。
